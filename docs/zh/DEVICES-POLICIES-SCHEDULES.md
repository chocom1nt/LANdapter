# 设备清单、组策略与计划任务

本文说明当前已实现的设备清单、策略和计划任务功能。设备清单用于诊断，并不代表系统会自动推荐或安装驱动。

## 设备清单

- Windows 在可用时使用 Plug and Play/WMI 信息，包括 Hardware ID、制造商、驱动提供方/版本和设备问题代码。Linux 通过系统接口检查 PCI/USB 设备及驱动绑定。
- 由于系统权限、设备类型、WMI 状态或工具缺失，部分字段可能为空。不完整结果与成功获取的空列表不同。
- LANdapter 提供诊断线索，但不会搜索厂商目录、下载驱动、验证签名或自动安装驱动。

## 组策略

- 策略将已上传软件包与操作系统子字符串过滤条件关联，并可手动下发。
- 持久化动态分组、AD/LDAP 目标选择、标签和高级目标规则尚未实现。
- 请先在测试工作站验证策略，并检查软件包来源、签名、参数、重启行为和幂等性。

## 计划任务

- 计划任务会按配置间隔重复安装策略中的软件包，目前不是通用任务引擎，也不支持完整的 cron 日历语义。
- 重复执行可能重新安装或修复软件，甚至触发重启。请使用可信且幂等的安装程序并监控任务结果；替换软件包或目标前先停用计划任务。

## 运维安全

- 大规模部署前先使用测试客户端。在不可信网络中，应限制 Master HTTP/WebSocket 端点或通过 TLS/WSS 保护。
- 备份 PostgreSQL 和 uploads。数据库清理/重置属于破坏性操作，不应作为日常维护手段。
