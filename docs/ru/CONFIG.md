# Конфигурация LANdapter

**Языки:** [English](../en/CONFIG.md) · [Русский](CONFIG.md) · [中文](../zh/CONFIG.md) · [日本語](../ja/CONFIG.md) · [Español](../es/CONFIG.md)

В этом документе описаны все параметры конфигурационных файлов `master.yaml` и `agent.yaml`, а также способы их переопределения через переменные окружения.

---

## Общие принципы

LANdapter использует [Viper](https://github.com/spf13/viper) для управления конфигурацией. Поддерживаются:

- YAML-файлы (основной способ)
- Переменные окружения (имеют приоритет над значениями из файла)
- Конфигурация перечитывается при перезапуске процесса; горячая перезагрузка в текущей версии не включена.

Конфигурационные файлы читаются из папки `configs/` относительно рабочей директории процесса. Аргумент `--config` в текущей версии не реализован; при запуске важно указать корректный рабочий каталог.

## Конфигурация мастера (`master.yaml`)

Файл `master.yaml` содержит настройки HTTP- и WebSocket-серверов, а также подключения к базе данных.

### Основные параметры

| Поле | Тип | Описание | Значение по умолчанию |
|------|-----|----------|----------------------|
| `host` | string | IP-адрес или имя хоста, на котором сервер будет слушать входящие соединения. `0.0.0.0` означает все интерфейсы. | `"0.0.0.0"` |
| `http_port` | int | Порт для HTTP REST API. | `8080` |
| `ws_port` | int | Порт для WebSocket-соединений с агентами. | `8081` |
| `db` | object | Настройки подключения к PostgreSQL (см. ниже). | – |

### Параметры `db`

| Поле | Тип | Описание |
|------|-----|----------|
| `host` | string | Хост базы данных (например, `localhost` или IP). |
| `port` | int | Порт PostgreSQL (по умолчанию `5432`). |
| `user` | string | Имя пользователя БД. |
| `password` | string | Пароль пользователя. Задавайте через `DB_PASSWORD` в окружении, а не коммитьте в YAML. |
| `dbname` | string | Имя базы данных. |
| `sslmode` | string | Режим SSL: `"disable"`, `"require"`, `"verify-ca"`, `"verify-full"`. Для разработки обычно `"disable"`. |

### Пример `master.yaml`

```yaml
host: "0.0.0.0"
http_port: 8080
ws_port: 8081
db:
  host: "localhost"
  port: 5432
  user: "landapter"
  password: "" # set DB_PASSWORD in the Master process environment
  dbname: "landapter"
  sslmode: "disable"
```

## Конфигурация агента (`agent.yaml`)

Файл `agent.yaml` определяет, как агент подключается к мастеру и как он выполняет установку.

### Основные параметры

| Поле | Тип | Описание | Значение по умолчанию |
|------|-----|----------|----------------------|
| `master_host` | string | IP-адрес или доменное имя мастера. | – |
| `master_port` | int | WebSocket-порт мастера (должен совпадать с `ws_port` в конфиге мастера). | `8081` |
| `master_http_port` | int | HTTP(S)-порт Master API для скачивания файлов агентом. | `8080` |
| `master_scheme` | string | `ws` для доверенной локальной сети или `wss` через TLS-прокси. | `ws` |
| `uuid` | string | UUID, выданный в Settings. Необязательно, если UUID уже хранится в `uuid_file`. | – |
| `token` | string | Персональный токен агента из Master Settings. Обязателен; храните как секрет. | – |
| `uuid_file` | string | Путь к файлу, в котором сохраняется уникальный идентификатор агента. Если файл не существует, он будет создан. | `"./agent.uuid"` |
| `installer_args` | object | Сопоставление расширений файлов с дополнительными аргументами командной строки (см. ниже). | `{}` |

### Параметр `installer_args`

Используется для переопределения аргументов установщика для конкретных типов файлов. Ключ — расширение (с точкой), значение — строка аргументов, которые будут переданы программе установки.

Например:
- Для `.exe` можно задать `"/quiet"` вместо стандартного аргумента тихой установки `"/S"`.

В текущем установщике параметры `.msi` задаются встроенной логикой (`/qn` для тихого режима и `/qb` для интерактивного); `installer_args[".msi"]` сейчас не используется.

Если аргументы не заданы, используются встроенные значения по умолчанию, зависящие от режима установки.

### Пример `agent.yaml`

```yaml
master_host: "192.168.1.100"
master_port: 8081
master_http_port: 8080
master_scheme: "wss"
uuid: "<issued-agent-uuid>"
token: "<issued-agent-token>"
uuid_file: "/var/lib/landapter/agent.uuid"
installer_args:
  ".exe": "/quiet"
  ".msi": "/qb"
```

## Переменные окружения

Все параметры из YAML-файлов могут быть переопределены переменными окружения. Viper автоматически преобразует имена: точка в ключах заменяется на символ подчёркивания, а регистр приводится к верхнему.

**Правила преобразования:**
- `db.host` → `DB_HOST`
- `http_port` → `HTTP_PORT`
- `master_host` → `MASTER_HOST`
- `installer_args` → `INSTALLER_ARGS` (но для map структура неудобна, лучше использовать файл)

**Пример задания переменных:**

```bash
export DB_HOST=postgres.example.com
export DB_PASSWORD=secret
export HTTP_PORT=9090
go run cmd/master/main.go
```

Это переопределит соответствующие параметры в конфиге мастера.

Для агента:

```bash
export MASTER_HOST=192.168.1.200
export UUID_FILE=/tmp/agent.uuid
go run cmd/agent/main.go
```

---

Административные REST-запросы требуют переменную `LANDAPTER_ADMIN_TOKEN` длиной не менее 32 символов. Выпускайте токены агентов в панели Master; сервер хранит только SHA-256-хеш. Для удалённых подключений используйте TLS-прокси и режим `master_scheme: wss`. Не коммитьте реальные секреты в YAML.

## Советы по безопасности

1. **Никогда не храните пароли в открытом виде в репозитории.** Используйте переменные окружения или отдельные секретные файлы (например, `master.secret.yaml`), которые добавлены в `.gitignore`.

2. **Ограничьте доступ к портам** через брандмауэр. HTTP-API и WebSocket не имеют встроенной аутентификации, поэтому они должны быть доступны только внутри доверенной сети.

3. **Используйте SSL/TLS** для PostgreSQL (`sslmode: "require"` или выше) в продакшн-среде.

4. **Периодически меняйте пароли** и не используйте стандартные (`postgres`/`postgres`).

5. **Для агента на Windows** рекомендуется запускать его с правами администратора, чтобы установка драйверов (`.inf`, `pnputil`) работала корректно.

## Проверка конфигурации

Для проверки корректности конфигурации можно запустить мастер или агент и посмотреть логи. При ошибках парсинга или отсутствии обязательных полей программа завершится с сообщением об ошибке.

---

## Изменение конфигурации во время работы

На данный момент конфигурация загружается один раз при старте. Для применения изменений требуется перезапуск процесса. В будущих версиях планируется поддержка горячей перезагрузки.
## Автономная работа агента и установка службой

Сейчас Agent — переподключающийся процесс, запущенный в foreground; репозиторий пока не устанавливает его как нативную службу Windows или systemd unit. Метрики и инвентарь запрашиваются по требованию, проактивные оповещения о событиях не реализованы. Для каждого Agent нужны собственные UUID и токен, выданные администратором. См. [жизненный цикл агента и автономное развёртывание](AGENT-LIFECYCLE.md): там объяснена причина этого ограничения безопасности и рекомендован будущий сценарий с bootstrap-токеном.
